## Anotações

Pipeline do compilador
Léxica >> Sintática >> Tipos >> Exec

Utiliza-se análise lexica para eliminar strings válidas, como comentato na aula 02.

Tem a fase dde análise sintática que verifica por exemplo sintaxe válida da gramática pertencente a gramatica.

Verificação de tipos é outra. Ela também elimina strings que não são válidos.
Por que ainda preciso de verificação de tipos depois de resolver o parsing? O parser não consegue fazer esse trabalho de verificar alguns programas (não é computacionalmente expressivo). Há programas que mesmo sendo sintaticamente válidos, não são semanticamente válidos.

Somar um inteiro com um real, por exemplo, estão fora da semantica de SML, por exemplo, isso não diz nada, então o programa tem que cortar isso de alguma forma.

Isso resolve com automatos do nivel __.
Léxica (T3) C(N) >> Sintática (T2) C(N3) >> Tipos (T1) >> Exec (T0)


Verificação de tipos nao é um problema que se resolve com uma gramatica livre de contexto.

Linguagem famosa que não tinha tipos: BCPL: introduziu a chave aberta e chave fechada. Não tinha tipos mas tudo era bytes.
BCPL nao tem suporte a numero flutuante

Existem programas que mesmo passando pela verificação de tipos tem comportamento não definido, porém alguns outros tem comportamento definido.

Comportamento indefinido: C, C++, Pascal (muitas coisas depende por exemplo da memoria alocada, em C o principal motivo disso éescrever arranjos fora do range que existe e isso é indefinido no programa).
Comportamento bem definido: Java, JS, Python (em python, por exemplo, todo valor carrega um rótulo do tipo dele).

Tipos são importantes pois evitam comportamento indefinido.

O que é um tipo?
Tipo é conjunto, alguns infinitos.

Em SML tem 5 tipos primitivos: int, real, boolean, string, char
Em JAVA: byte (8 bits), char (unicode), short (16 bits), int, long, double, boolean
Em C: (unsigned) int, float, char, (unsigned) short, (unsigned) long, double. Mas o tamanho em C nem sempre é definido, depende do compilador, pois nem sempre é 2^32.

## Cardinalidade
Cardinalidade se mede pelo produto (é o número de valores possíveis que ele pode assumir)

T1 * T2 : qual a cardinalidade disso? 

Em C, produtos cartersianos mais comuns são structs:

struct complex {
    double rp;
    double ip;
};

int main() {
    struct complex c1;

    c1.rp = 0;
    c1.ip = 10;

    printf("%d\n", c1.rp); // 0
    printf("%d\n", sizeof(double)); // 8
    printf("%d\n", sizeof(c1)); // 16

}

Esse exemplo é um jeito de mostrar que a cardinalidade é ∣𝑑𝑜𝑢𝑏𝑙𝑒∣ x ∣𝑑𝑜𝑢𝑏𝑙𝑒∣ ≈  2^64 + 2^64 = 2^128

sizeof é uma macro e executa em tempo de compilação

por que não da pra fazer o sizeof de uma struct em tempo de execução? Não tem seu tamanho guardado em lugar nenhum

Arranjos, vetores são outro exemplo de produto cartesiano.

Tupla é um produto de coisas diferentes, arranjos são produtos de coisas iguais.


Vetores em SML só tem 2 operações: ler a cabeça e ler a cauda

Em SML por exemplo não dá pra fazer um bucket sort pois nao da pra indexar elementos da lista.


Em R por exemplo é possível que um programa tenha mais vetores do que interios.



### União de 2 tipos

Em C por exemplo temos union.

struct nao_eh_union {
    int i;
    double d;

}

union element {
    int i;
    double d;
}

int main () {

    union element e0;
    struct nao_eh_union s0;
    e0.i = 1;

    printf("%d\n", e0.i); // 1
    printf("Union: %lu\n", sizeof(e0)); // 8
    printf("Struct: %lu\n", sizeof(s0)); // 16
}


cardinalidade pode ser soma

union em C é uma sobreposição de memoria, usa se muito union em compiladores em C. A representação de arvore abstrata o padrao para fazer isso em C é com union.
